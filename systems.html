The Mirèl method

One change.
Four decision points.

The work moves forward when the evidence and operating conditions support the next step.

  1. 01

    Diagnose

    Map the current task, its owner and the systems involved. Establish a baseline and record what the available data cannot show.

    Working output: Workflow map + baseline findings.

  2. 02

    Prioritize & design

    Choose the change worth testing. Specify the AI task, approved information, supported connections, staff review and expected value.

    Working output: Workflow specification + agreed test scope.

  3. 03

    Implement & validate

    Build within the agreed scope. Test routine cases, uncertain requests and failures with the people who will run the process.

    Working output: Test findings + launch and handover criteria.

  4. 04

    Review & improve

    Compare outcomes, staff effort, exceptions and running costs with the starting point. Decide what to keep, refine or stop.

    Working output: Review record + next decision.

Test the edges of the workflow

What happens when
the usual path breaks?

A reliable implementation needs a defined response to uncertainty and failure, alongside routine cases.

Example test case / Routine request

A booking question with enough information.

Incoming request
“Can you send me the consultation booking link?”
AI task
Prepare a draft using the clinic-approved booking guidance.
Team action
Reception checks the draft and sends the next step.
Recorded outcome
Track the inquiry until a booking or another outcome is recorded.

Example test case / Uncertain request

The request needs clinical judgment.

Incoming request
“Which treatment is right for my skin condition?”
AI boundary
Do not select a treatment or infer suitability.
Team action
Route the request to the clinic’s designated qualified professional.
Recorded outcome
Keep an assigned review task; do not mark the clinical question as resolved.

Example test case / Connection failure

A required system is unavailable.

Trigger
The booking connection cannot return a reliable result.
System boundary
Do not invent availability or confirm an appointment.
Team action
Keep the request in the source channel and assign manual follow-up.
Recorded outcome
Record the failed handoff for review and resume only after validation.
